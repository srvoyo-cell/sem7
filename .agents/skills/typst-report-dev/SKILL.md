# Отчёты в Typst

Подготовь содержательный отчёт по заданию пользователя и его пресетам. Сохраняй редактируемые исходники и, если доступен компилятор, проверенный PDF.

## Правила и шаблоны

Перед созданием или правкой отчёта прочитай `main_rules.md` из `C:\Users\misha\OneDrive\Документы\codex_\typst_presets`. Перед использованием модуля изучи его содержимое и сигнатуру функции. Если исходная папка недоступна, используй включённые в скилл копии:

- [Правила оформления](references/main_rules.md) — прочитай полностью, когда недоступен оригинал.
- [Титульный лист лабораторной работы](assets/title_page_lab.typ).
- [Титульный лист практической работы](assets/title_page_prac.typ).
- [Листинги и подписи таблиц](assets/listings.typ).

Включённые копии правил и шаблонов синхронизированы с исходной папкой 13 октября 2026 года. Доступные актуальные оригиналы предпочтительнее копий. Указания пользователя и требования к конкретной работе имеют приоритет над пресетами. При расхождении текста правил с реализацией модуля руководствуйся правилами и корректируй только копию модуля в проекте отчёта.

## Подготовка проекта

- Изучи задание, существующий отчёт и предоставленные результаты. Сохраняй заданную структуру проекта; для новой работы основной файл по умолчанию — `report.typ` в текущей директории, либо имя, указанное пользователем.
- Скопируй нужный титульный модуль и `listings.typ` в директорию отчёта; используй относительные импорты. Существующие локальные модули сначала сравни с пресетами, чтобы сохранить доработки пользователя. Расчётные и вспомогательные скрипты храни отдельно от Typst-файлов.
- Не придумывай результаты экспериментов, исходные данные, реквизиты преподавателя или ссылки на источники. Недостающие обязательные сведения запроси, продолжая независимые части работы. В явно запрошенном черновике допустимы заметные заполнители, о которых нужно сообщить при передаче.
- Для нового отчёта используй структуру из правил: титульный лист, содержание, введение, разделы по заданиям, заключение. Структура подразделов по заданиям — ориентир; подбирай её под фактическое содержание. Приложения и список использованных материалов добавляй, если они нужны по заданию или запросу пользователя; не возвращай разделы, которые пользователь попросил удалить из конкретного отчёта.

## Титульный лист

На титульном листе задавай межстрочный интервал `leading: 0.5em` локально внутри функции `title_page`: `set par(leading: 0.5em)`. Это сохранённая настройка пользователя; применяй её и при копировании внешнего пресета с другим значением. Она относится только к титульному листу; для основного текста сохраняй интервал из правил.

Выбери `title_page_lab.typ` для лабораторной или `title_page_prac.typ` для практической работы. Оба экспортируют `title_page` с одинаковой сигнатурой. Пример вызова с уже определёнными данными:

```typst
#import "title_page_lab.typ": title_page
#title_page(
  номер_работы,
  предмет,
  вариант,
  проверил: (должность: должность_преподавателя, фио: фио_преподавателя),
)
#pagebreak()
```

Первые три аргумента позиционные. Параметр `проверил` фактически требует словарь с ключами `должность` и `фио`: значение по умолчанию `()` не обеспечивает этих полей.

В пресетах зафиксированы вуз, кафедра, профиль, группа Б23-183-1, М. А. Панин, город и 2026 год. Учитывай эти пользовательские значения; изменяй локальную копию по данным конкретного задания. Не подменяй год отчёта текущим годом автоматически.

## Применение оформления

Все численные настройки бери из прочитанных правил. Основные параметры: Times New Roman 14pt для текста; `leading: 0.65em` и `spacing: 0.65em` без увеличенного промежутка между абзацами; `first-line-indent: (amount: 1.25cm, all: true)` для всех абзацев основного текста, включая первый после заголовка. У заголовков, подписей, таблиц и листингов локально сбрасывай красную строку до `0pt`. Интервалы вокруг блочных объектов задавай независимо через `block(above:, below:)`.

- Титул и содержание без напечатанных номеров; после разрыва перед введением включи нумерацию. Правила задают начало с 3 при одностраничных титуле и содержании. Если содержание занимает больше страницы, проверь физический номер первой страницы текста и согласуй счётчик с ним, не оставляя ошибочное значение 3.
- У содержания не допускай двойного заголовка: при ручном «СОДЕРЖАНИЕ» используй `outline(title: none, ...)`. Записи первого уровня — жирные.
- Подключай `setup-listings`, `listing`, `tbl-caption` из локального `listings.typ` и применяй `#show: setup-listings`. Не дублируй правило оформления блочного `raw` в основном файле.
- Шрифт листингов — Courier New 11pt, номера строк — Courier New 9.5pt. Подписи остаются Times New Roman 14pt. Применяй эти настройки внутри модуля, включая строки `raw`, создаваемые для нумерации; глобальное оформление строчного кода не должно их переопределять. Короткие листинги и таблицы удерживай вместе с подписью на одной странице.
- В листингах оставляй только существенный код без комментариев; пояснения пиши в основном тексте. Это ограничение относится к коду, показываемому в отчёте, а не требует удалять комментарии из исходных программ пользователя. Номера листингов — N.M внутри задания.
- Подписи листингов и таблиц размещай сверху слева; подписи рисунков — по центру в полноширинном блоке, обычно снизу. Управляй интервалами подписи и объекта раздельно, без красной строки.
- Формулы и единицы оформляй средствами математического режима Typst по примерам правил, включая `dot`, степени и `approx`.

## Проверка и передача

Скомпилируй основной файл из директории отчёта, например `typst compile report.typ report.pdf`, подставив реальное имя. Если нужен уточняющий поиск синтаксиса, используй доступную документацию Typst; не делай работу зависимой от конкретного MCP-сервера.

Разбери ошибки и предупреждения компилятора. Проверь доступность требуемых шрифтов через `typst fonts`; не считай незаметную замену шрифта соблюдением требований. При отсутствии компилятора или нужного шрифта явно сообщи, какая проверка или часть оформления осталась незавершённой.

Просмотри скомпилированные страницы средствами просмотра PDF или рендерингом в изображения. Особенно проверь титул (распределение свободной высоты и размещение реквизитов на одной странице), содержание, первую нумеруемую страницу, длинные листинги и таблицы. Исправь выход за поля, наложения, лишние пустые страницы и отрыв подписей от объектов. Успешной компиляции недостаточно для утверждения, что вёрстка проверена.

Передай ссылки на основной `.typ` и готовый PDF, если он собран. Сохрани локальные модули и используемые изображения рядом с проектом, чтобы повторная сборка не зависела от абсолютных путей к личным пресетам. Кратко отметь только реальные недостающие данные или незавершённые проверки.
